# Инструкции для Cursor / AI-агента

## Цель
Реализовать учебные работы КТ №1–12 по дисциплине «Модульное тестирование веб-приложений».
Перед началом каждого этапа прочитай README.md, docs/ASSIGNMENTS.md и docs/STATUS.md.

## Основные правила
- Работай **по одной КТ** или заранее согласованному блоку. Не реализуй все 12 КТ одним большим коммитом.
- Пользователь работает в Windows. Для базовых web-тестов используй Python 3 + pytest + Selenium 4, Page Object в selenium/pages/.
- Для Appium используй совместимые с установленной версией Appium Python Client API и UiAutomator2; не копируй устаревшие desired_capabilities, find_element_by_id и TouchAction без адаптации.
- Для Selenium Grid используй Selenium 4 и актуальный URL Grid, опиши реальную конфигурацию и процедуру проверки.
- Robot Framework: минимум 10 **различимых** тест-кейсов, их результаты и отчёты.
- gRPC: минимум 10 **различимых** тест-кейсов; локальный пример сервиса допустим, если в презентации нет иных требований.
- Для тестов нужны проверяемые assertions, таймауты и надежные ожидания; не используй time.sleep без крайней необходимости.
- Не объявляй тесты успешными без реального запуска. Если браузер, эмулятор, Appium или Grid не установлены, честно отметь NOT RUN и дай команды для запуска.
- Для каждой КТ документируй: цель, среду, зависимости, команды, тест-кейсы, фактические результаты, скриншоты и вывод.
- Публичные сайты могут изменять верстку или показывать капчу; не обходи ограничения и не делай нагрузочный тест на стороннем сайте.
- Не коммить .env, секреты, токены, Chrome-профили, приватные данные. Не отправляй изменения в GitHub, пока пользователь явно не разрешил push.
- Не изменяй unrelated файлы. Делай небольшие логические коммиты с понятным сообщением.
- При фиксации бага отличай баг продукта от ошибки окружения/теста.

## Формат отчета после каждого этапа
1. КТ и какие требования выполнены.
2. Какие файлы созданы/изменены.
3. Точные команды для повторного запуска.
4. Фактические результаты PASS/FAIL/SKIP/NOT RUN с доказательствами.
5. Риски, ограничения и что нужно для следующей КТ.
6. Статус git (ветка, коммиты, есть ли незакоммиченные изменения).

## Правила отчётности
Отдельные отчёты для сдачи сохранять как reports/KT01.docx ... reports/KT12.docx.
Скриншоты положить в screenshots/kt01/ ... screenshots/kt12/. Не создавать фиктивные скриншоты или результаты тестов.
Обновляй docs/STATUS.md только по факту выполненной работы.
