# КТ05 — Рекомендации

Основаны на фактических прогонах VDNH news (9/1 + follow-up PASS).

## По продукту / сайту

1. Явных дефектов раздела новостей в исполненных сценариях **не подтверждено**.
2. Рекомендуется (общие наблюдения для динамических лент): стабильные `data-testid` на кнопке
   «Показать ещё» и карточках — упростит стороннюю автоматизацию и снизит flakiness.

## По процессу тестирования

1. Сохранять честное разделение полного прогона и целевых follow-up (не склеивать в «10/10»).
2. Для публичных тяжёлых сайтов использовать `pageLoadStrategy=none` + DOM waits, не `time.sleep`.
3. Условия успеха подгрузки делать составными (cards **или** links **или** URL).
4. Периодически перепроверять локаторы — вёрстка новостных порталов меняется.
5. Risk-based: P0 (лента/статья) гонять чаще, чем P2 (logo/menu).

## По документации КТ05

1. White-box для закрытого backend не заявлять.
2. Дефекты продукта и проблемы автотестов вести раздельно (`defect-analysis.md`).
