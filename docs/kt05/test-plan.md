# Тест-план — КТ 05 (функциональное тестирование VDNH)

## 1. Цель

Проверить ключевой функционал публичного раздела новостей сайта **ВДНХ**
(`https://vdnh.ru/news/`) и оформить комплект тестовой документации по требованиям преподавателя
(выбор сайта, стратегия, сценарии, выполнение, дефекты, рекомендации, итоговый отчёт).

Референс: [sa-teach/selenium-tests](https://github.com/sa-teach/selenium-tests)
(структура Page Object / тест-план; локаторы перепроверены на актуальной вёрстке).

Обоснование выбора сайта: `docs/kt05/website-selection.md`.

## 2. Объект тестирования

| Элемент | URL / область |
|---|---|
| Главная | `https://vdnh.ru/` |
| Лента новостей | `https://vdnh.ru/news/` |
| Карточка новости | `https://vdnh.ru/news/<id>/` |

Доступность (2026-10-09): сайт отвечает; полный `page load` в Chrome часто зависает на фоновых
ресурсах. Рабочая стратегия: `pageLoadStrategy=none` + явные ожидания DOM.

## 3. Пользовательские сценарии (бизнес)

1. Гость открывает главную ВДНХ и убеждается, что сайт доступен.
2. Гость переходит в раздел «Новости» и видит заголовок/ленту.
3. Гость просматривает карточки с осмысленным текстом и ссылками.
4. Гость открывает статью и читает заголовок/содержание.
5. Гость возвращается к ленте.
6. Гость подгружает дополнительные карточки («Показать ещё»).
7. Гость использует логотип/меню для навигации.

## 4. Объём (scope) и исключения

**В объёме:** сценарии 1–7; black/gray-box техники; автотесты Selenium + Page Object; скриншоты.

**Вне объёма:** авторизация, личный кабинет, оплата, поиск по всему сайту, нагрузка, SEO,
pixel-perfect, мобильная вёрстка (отдельно — KT09/KT10), white-box backend.

## 5. Методы и техники

| Техника | Применение в KT05 |
|---|---|
| **Black-box** | Пользовательские сценарии без знания серверной логики: открытие страниц, клики, видимость заголовков |
| **Gray-box** | DOM/CSS-локаторы, структура URL `/news/<id>`, `document.readyState`, счётчик карточек/ссылок |
| **White-box** | **Не применим** — backend VDNH закрыт; исходники сервера недоступны |
| Boundary / negative | Косвенно: пустая лента не ожидается; конкретные заголовки новостей **не** зашиваются (избегание хрупких ожиданий) |
| Risk-based | Приоритет P0: открытие новостей + карточки + статья; P1: show_more; P2: logo/menu |

## 6. Критерии входа / выхода

**Вход:**
- Windows + Chrome + `.venv` + `selenium/requirements.txt`
- Локальный/Selenium Manager ChromeDriver
- Сайт `vdnh.ru` доступен без VPN (или с документированным обходом)
- Тестовые данные не требуются (публичный read-only контент)

**Выход:**
- ≥ 8 осмысленных автотестов с assertions
- Документация: plan / cases / RTM / report / selection / defects / recommendations
- Скриншоты `screenshots/kt05/`
- Отчёт `reports/KT05.docx`
- Результаты зафиксированы честно (исторический FAIL, follow-up, remediation 10/10)

## 7. Тестовые данные

| Данные | Значение |
|---|---|
| Учётные записи | Не используются |
| URL | `https://vdnh.ru/`, `https://vdnh.ru/news/` |
| Динамический контент | Заголовки новостей **не** фиксируются в assertions |

## 9. Риски

- Изменение вёрстки VDNH → поломка локаторов.
- Тяжёлые скрипты/таймауты renderer.
- Динамический контент.
- Подгрузка «Показать ещё» зависит от клиентского JS/XHR (флейк возможен).
- Путаница дефекта сайта vs ошибки теста (см. `defect-analysis.md`).
